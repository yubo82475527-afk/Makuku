## 1. 文档说明

### 1.1 本说明书回答什么

- 系统当前覆盖哪些经营能力
- 三类读者各自看什么、做什么
- 各功能模块的入口、核心操作与结果去向
- 哪些菜单是示意占位、哪些能力尚未对业务开放

### 1.2 范围边界（1.0）

**在范围内：** 终端采价 → AI 识别 → 价格审核 → 真实价格沉淀 → 价格指数 / 报表查看。

**不在范围内（除非另行开放）：** 铺货、陈列、货架 OSA、缺货与可见度分析；复杂动作目录与预算池；促销/竞品专家 Agent 自动编排。

### 1.3 核心业务闭环

```text
主数据准备
  → 终端巡店采价（H5）
  → AI 解析与质量门禁
  → 人工价格审核（运营）
  → 确认价格进入真实价格
  → 价格指数 / 报表（区域负责人、分析人员）
```

系统价值不在「有多少次拜访」，而在：**价格事实是否可信、偏差是否可见、能否支撑区域经营判断**。

## 5. 功能模块说明

### 5.1 价格指数

**用途：** 以周为粒度展示自有与竞品价格系数，支持按组织及下级地理/商品维度展开，服务区域经营看盘。

**主要能力：**

- 筛选：月份、组织、自有系列、自有包装、竞品包装
- 布局：可配置展开维度（组织固定；可选省/市/区、尺码、SKU），偏好保存在本地浏览器
- 展示：树表形式的单片价与系数
- 导出：支持价格指数导出（Sheet1 指数矩阵；Sheet2 为与指数同源的去重明细）

**选价口径：**

- 每个自然月固定四周（W1–W4）内，同一门店同一商品（自有按 SKU、竞品按竞品商品）只取 `captured_at` 最新一条确认快照，再跨店算术平均并计算系数
- 系数 = 标杆均价 / 该品牌均价（保留两位小数）；实际用作基期的标杆列系数为 1。未设置竞品默认标杆时，自有均价为标杆且自有系数为 1；已设置且该标杆本周有有效均价时，全表以该竞品均价为基期；已标记但本周无有效均价时回退为自有作基期（该竞品列系数为空）
- 单元格采样量 = 去重后的有效「店×商品」条数
- 导出 Sheet2、以及从指数单元格穿透进入真实价格（`priceIndexDrill=1` 首屏）均只展示上述指数样本，可与均价/采样量对账
- 从菜单进入真实价格、或在真实价格页改筛后重新查询：仍展示筛选范围内全部确认快照（事实底账）

**读者关注点：**

- 区域负责人：先看本组织系数与竞品差距，再展开到城市/SKU
- 分析人员：核对维度口径与导出结果是否满足复盘需要

---

### 5.2 真实价格

**用途：** 浏览已确认的价格快照明细（自有 + 竞品），是价格指数与分析结论的事实底账。

**主要能力：**

- 主筛选：商品归属（全部/自有/竞品）、品牌、系列、尺码、采集日期
- 更多筛选：省市区、门店、SKU、巡店编号、组织
- 列表字段：采集时间、品牌、商品、SKU、包装、规格、片数、活动类型、标价、折扣、到手价、单片价、门店、省市区、采集人、创建时间、巡店编号、图片编号等
- 导出；勾选后批量删除（面向测试数据清理，生产慎用）
- 分页：默认 50，最大 200
- 受会话数据范围约束

**读者关注点：**

- 分析：导出做外部分析前，先确认筛选条件与数据范围
- 运营：删除仅影响价格快照，不替代正式纠错流程

---

### 5.3 巡店记录

**用途：** 监控巡店上传、AI 分析状态、耗时与价格解析质量；支持按拜访 / 导购 / 门店视图查看。

**主要能力：**

- 筛选：巡店编号、门店、促销员、分析状态、日期
- 分析状态：待处理、分析中、已完成、部分完成、需处理、失败
- 指标：已分析巡店数、耗时分位、需处理失败数、平均图片数；可展开价格解析质量（准确率、自动通过率、平均价格偏差）
- 导出：按当前视图异步导出
- 管理员可对单次拜访或日期范围「重跑匹配」

**读者关注点：**

- 运营：优先处理「需处理 / 失败」，避免候选积压
- 区域负责人：按导购/门店看覆盖与通过率，推动执行补强

---

### 5.4 价格审核

**用途：** 对进入事实层前的 AI 价格候选做人工确认，是价格治理的核心工作台。

**主要能力：**

- Tab：待处理 / 已处理
- 筛选：日期、拍照批次（巡店编号）、异常原因
- 常见异常原因（节选）：无法确认商品、同规格多 SKU、价签不清、片数不清、包装价/片数冲突、单片价需确认、缺证据、相对基准偏差偏大、促销价、历史样本不足、系统校验失败等
- 单条动作：确认；修改包装价与片数；改商品匹配；判定为错误
- 导出审核列表；导出未匹配；导入匹配结果

**读者关注点：**

- 运营：先处理高风险原因（价看不清、偏差大、匹配错误），再处理可快速确认项
- 区域负责人 / 分析：一般不日常审价；若发现指数异常，可请运营按巡店编号回查审核轨迹

**数据含义：** 候选通过后才会进入真实价格；未审核完成会阻断可信价格沉淀。

---

### 5.5 竞品对标

**用途：** 维护竞品系列 → Makuku 系列的映射，并为竞品 SKU 设置默认标杆，支撑价格指数对比口径。

**主要能力：**

- 筛选：竞品品牌、系列
- 动作：保存并应用规则、删除规则；设为 / 取消 / 清除标杆
- 字段：竞品品牌、竞品系列、Makuku 系列、适用 SKU 数、默认标杆

**读者关注点：** 运营维护；分析在发现「对比对象不合理」时应反馈运营改规则，而不是只在报表里手工改口径。

---

### 5.6 商品匹配规则

**用途：** 维护「原始识别写法 → 规范值」规则，供新巡店解析与匹配重跑共用，减少重复人工纠错。

**主要能力：**

- 字段类型：品牌、系列、尺码、片数
- 新增 / 编辑 / 删除（删除后停止对新解析生效，保留历史）
- 规范值须落在启用主档中；片数规则有额外校验约束

**读者关注点：** 运营在价格审核中反复遇到同一错写时，应沉淀为规则，而不是每次只改单条候选。

---

### 5.7 自有产品

**用途：** 导入与查看 Makuku 物料主数据；维护商品等级（segment）。

**主要能力：**

- Excel/CSV 导入（固定列顺序，含物料编码、名称、品类、品牌、系列、片数、箱规、片单价等）
- 商品等级行内维护
- 等级维护在主数据侧，不直接写入价格快照

---

### 5.8 竞品产品

**用途：** 维护竞品 SKU 主数据，支撑匹配、对标与价格展示。

**主要能力：**

- 筛选：品牌、关键词、尺码、启用/禁用
- 导出；Excel 导入（独立导入页）
- 抽屉编辑（编码锁定，其余可改）

---

### 5.9 门店

**用途：** 门店主数据查询与组织归属、启停管理。停用后门店不再出现在移动端选店列表。

**主要能力：**

- 筛选：状态、组织（含未分配，视权限而定）
- 批量改组织；单店 / 批量启用禁用
- 受数据范围限制

---

### 5.10 报表中心

**用途：** 管理报表订阅、查看发送记录、预览模板，并支持重新生成 / 重新投递。

**当前启用范围：**

- 已启用：`Daily Price Country Report`（国家日价格报表）
- 组织日/周、管理周、月报等定义可能存在于系统中，但当前未对业务列表启用

**主要能力：**

- 订阅对象：用户 / 飞书聊天
- 范围：global / organization / user
- 日程：日 / 周 / 月；可启停
- 发送记录：状态、命中订阅、投递摘要、生成时间

## 6. 数据从哪里来（采价链路说明）

PC 读者需要理解上游来源，但不一定自己操作移动端。

| 步骤 | 说明 |
| --- | --- |
| 1. 移动端提交 | 巡店人员在 H5「离线采价」选择组织/门店，上传货架/价签照片并提交 |
| 2. AI 分析 | 系统解析商品与价格，生成候选；巡店记录可见分析状态 |
| 3. 质量门禁 | 部分候选可自动通过；风险或异常进入人工审核 |
| 4. 人工审核 | 运营在「价格审核」确认或纠正 |
| 5. 事实沉淀 | 通过后进入「真实价格」，再支撑「价格指数」与报表 |

**拍照质量要求（影响识别成功率）：** 正对价签、靠近货架、一张一小区域、数字清晰；避免整排斜拍。

## 8. 常见问题（功能口径）

| 问题 | 说明 |
| --- | --- |
| 为什么价格指数和我感觉的市场价格不一致？ | 先核对组织数据范围、对标规则、审核是否积压、真实价格样本是否覆盖目标城市/SKU |
| 巡店已完成，为什么真实价格没有？ | 可能仍在分析、卡在质量门禁，或待人工审核；到巡店记录与价格审核按巡店编号追踪 |
| 审核里总是匹配不上商品？ | 检查竞品主数据是否齐全，并在「商品匹配规则」沉淀规范写法 |
| 区域负责人看不到部分门店/价格？ | 检查角色数据范围是否为「按组织」，以及门店是否已归属正确组织 |
| 能否在真实价格里直接改历史价格？ | 已确认事实不以「原地改数」为标准纠错方式；应通过候选治理/更正流程处理 |

## 附录 A. 分析状态速查（巡店记录）

| 状态 | 含义 |
| --- | --- |
| 待处理 | 已提交，等待分析 |
| 分析中 | AI 正在处理 |
| 已完成 | 分析完成 |
| 部分完成 | 部分图片/结果完成 |
| 需处理 | 需要人工介入（如补拍、失败重试） |
| 失败 | 分析失败 |
