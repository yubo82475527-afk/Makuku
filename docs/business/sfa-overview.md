# SFA 业务总览

## 系统使命

Makuku SFA 服务于快消品区域经营管理。系统以区域负责人为主要经营视角，把目标、执行、异常、复盘和调整连接成可追踪的闭环，最终提升销售效率和经营能力。

系统不以记录销售行为为终点。页面、流程和 AI 能力都应帮助管理者回答三个问题：

1. 当前经营结果与目标之间有什么差距？
2. 差距发生在哪里，原因是什么？
3. 谁应该在什么时间采取什么动作？

## 核心角色

| 角色 | 主要职责 | 系统关注点 |
| --- | --- | --- |
| 总部管理者 | 制定整体策略和经营要求 | 跨区域趋势、重大异常、策略执行结果 |
| 区域负责人 | 对区域经营结果负责 | 目标差距、重点异常、资源与动作调整 |
| 城市经理 | 管理城市范围内的执行 | 城市目标、团队执行、问题跟进 |
| 业务代表 | 完成终端业务动作 | 清晰任务、执行标准、反馈结果 |
| 经销商 | 配合渠道销售和终端服务 | 供货、价格和协同执行 |
| 门店 | 承载终端销售与市场事实 | 商品、价格、活动及历史变化 |

## 经营闭环

### 目标

每项功能首先要说明它解决的经营问题，而不是只描述系统动作。目标应能关联经营对象、时间范围和判断标准。

### 执行

明确实际业务动作、执行角色、执行时间和执行标准。系统中的任务、采集或审核记录，应能还原真实业务过程。

### 异常

异常必须可识别、可追踪、可分析。异常定义至少应包含判断规则、影响对象、严重程度、责任归属和当前状态。

### 复盘

复盘不只是展示指标。系统应支持查看结果、定位原因、比较历史，并沉淀处理结论。

### 调整

分析结果最终要落到明确动作，包括责任人、完成时间、预期结果和后续验证。AI 建议也应服务这一闭环，而不是停留在文字报告。

## 产品设计检查

设计页面、字段或流程时，优先检查：

- 区域负责人能否快速看到目标差距和重点异常？
- 数据能否定位到需要关注的区域、渠道、SKU、门店或责任人？
- 用户能否从异常进入原因证据，再形成后续动作？
- 动作完成后，系统能否验证结果并保留历史？
- 展示的是经营结论，还是缺乏上下文的数量堆积？

例如，相比“今日拜访 100 次”，更有经营价值的表达是“重点门店覆盖率 85%，20 家核心门店未完成计划动作”。
